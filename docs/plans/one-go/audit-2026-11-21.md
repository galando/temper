# Independent audit of the 9.8.5 build

An audit of the build branch of pull request 117 against the plan `docs/plans/two-approval-run.md`, by agents that
did not build the branch. It read commit `dc108ee` on 2026-11-21, while the build was in its last package. On
2026-11-22, after the build ended, every finding that was not fixed was tested again on `57b4cb6`, and the fixes the
build made after `dc108ee` were audited too. The last commit of the build, `01af4e4`, adds only its summary; no code
changed after `57b4cb6`.

## How it was made

- Eleven auditors, one for each part of the plan. Each read the code, ran it, and broke a behaviour on purpose to
  see whether its check notices.
- Every gap an auditor reported went to a second agent whose job was to refute it. 104 gaps were reported, 25 were
  refuted, and 79 stood.
- The gaps that stood were tested again on the final code. The high and medium ones were tested twice, on `5fe91a6`
  and on `57b4cb6`.
- Two more auditors read the 63 fixes the build made after `dc108ee`. They reported 16 new gaps; a second agent
  refuted 6, and 10 stood.
- No model was called. Every run used the scripted agents of `scripts/e2e` or the CLI alone.

## What to do with it

For each finding that is open: reproduce it on your newest commit first. If it reproduces, write the check that
fails, then the fix. If the plan or a recorded decision allows it, say where. If it is a decision for the owner, put
it in the list for the owner. Never make a check pass by loosening it. Start with the high finding and the medium
ones; the low ones are in `audit-2026-11-21-low.md`.

### NEW-RULES-1 (high): One `evidence run` of `true` under the acceptance claim or the regression proof claim turns a FAIL verdict to PASS

**The promise:** Rule 5 (two-approval-run.md section 8): "Every verdict is computed by the CLI from runs the CLI
made or you confirmed, and names the tree it judged." Rule 7: "Tests come first, and the tests that gate the code
are written and locked by an agent that did not write it." done.md rows D34 and D36.

**What the second checker found first:**

enough).

  confirmed, and names the tree it judged."
- Rule 7: "Tests come first, and the tests that gate the code are written and locked by an agent that did not write
  it."
- done.md D34 and D36 restate both rules word for word. D36b adds that a locked test changed after the lock fails

Why the promise is broken and not merely stretched:
- Read literally, the run of `true` is "a run the CLI made". But the build's own code puts this case under rule 5:

- The passed row then says "they pass, unchanged since they were locked" while the locked test still exits 1 on the
  same tree. The locked tests no longer gate the code, which is rule 7.
- In an unattended run, `next` becomes `auto state advance build_complete review`, so the run goes on by rule.

Not a recorded deviation: PROGRESS.md has no note leaving these rows open. Its "left on purpose" list (line 289)
names other items, and the "Proves less" notes of D34 and D36 admit different limits. The D34a check covers only
`evidence add`.

Not checked by running: the mod's rule engine. I only read it; `hooks/temper-mod/core/rules.ts` has no rule on
`evidence run` or its claim, and tests/mod/hardening.test.ts:541 lists such a call as allowed.

Severity high: one Bash call with no person involved flips a section 8 rule, and it is the same hole the build's own
review fixed in three sibling rows.
