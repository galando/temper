# Done: every promise of the one pass build, and the check that proves it

The result is done when every row of the table below holds. WP07 writes the checks before the changes that make
them pass; `scripts/selftest/expected-fail.txt` lists the ones that still fail and must be empty at the end.

This page stands in for the owner's review of one large pull request. So it also says, row by row, where a check
proves less than its promise, and which rows no command can check.

## How to read a red row

For the build session. A row is your "done" of a package, beside its spec; the last section lists the rows by
package.

1. **Red, or only not due yet?** `python3 scripts/check_done.py` prints each row as `ok`, `expected to fail` or
   `open`. A check that fails while its line is on `scripts/selftest/expected-fail.txt` is not red. A row whose
   fourth cell is `no` or `person` is `open` until its evidence is there; a bench row that ran and missed its
   line is reported with its numbers and never tuned (note 2). Red is: a check that fails with no line on the
   list, a listed check that passes, and, at `bash scripts/verify.sh final`, any line left on the list.
2. **Whose is it?** Find the row under "Rows by package". Its package is not built yet: the check goes on the list
   with that package, and you go on. Its package is built: the package is not done, go back to it.
3. **Run the one check.** `TEMPER_CASES_ONLY=44 bash scripts/selftest/test-temper.sh` for a `case 44` item,
   `bun scripts/e2e/run.ts plain <name>` for a scenario, the command itself for a `gate` item. Every assertion
   starts with its row id, so the first failing line names the promise.
4. **Repair the product, never the check.** Do not change what an assertion asserts, raise a `final`, take a stop
   out of `scripts/stops.json`, delete a line of the list for a check that does not pass, add a skip, or change
   this table to fit the tree.
5. **Green too early or too late.** A row that passes before its package leaves the list in that commit. A row
   marked "kept by" that turns red in a later package was broken by that package: repair it there, before its
   commit. Its line never goes back on the list: `scripts/check_done.py` fails on a token that left the list and
   came back.
6. **A check that is wrong.** Only a name is wrong (a call, a row, an option id that `contracts.md` spells in
   another way): correct the name and list the change in `docs/plans/one-go/changed-tests.md`. What it asserts is
   wrong, or a cap, a floor or a mechanism cannot be met: do not edit it. Write the row id, the reason and the
   measured number under "Found on the way" in `docs/plans/one-go/PROGRESS.md`, leave the line on the list, name
   the row under "Not done" in the pull request text, and go on with every package that does not depend on it.
   The owner decides; you never do.

## How to read the table

- **Id.** The id is the first word of the name of every selftest assertion that proves the row (`D31a`, `D31b` are
  two assertions of row `D31`). A token is compared as a whole word, so `D10` never matches `D100`.
  `scripts/check_done.py` reads the table under the heading "The table" and no other table of this page: keep its
  five columns and its ids.
- **Promise.** The promise in the final state, version 9.8.5. Where the plan gives a number for a middle release,
  the number here is the one after release 7. "9.8.5" is always the result; the tree the build starts from is
  "the base (`10e965a`)", and what users have is 9.8.4 (`7c7a1c1`).
- **Check.** Each item starts with its suite:
  - `case NN <token>`: an assertion of `scripts/selftest/temper-cases-NN.sh` whose name starts with the token. The
    token is the row id, with a letter when a row has several; a row may also name the token of another row.
  - `scenario <name>`: a scripted run of `scripts/e2e/accept.ts`, `scripts/e2e/slow.ts` or `scripts/e2e/broken.ts`,
    run by `bun scripts/e2e/run.ts <mode> <name>`. With no mode named it runs in plain, mod and driver mode.
  - `floor <key>`: a `final` value of `scripts/e2e/floor.json`, held by `python3 scripts/check_floor.py --final`.
  - `caps <key>`: a `final` value of `scripts/caps.json`, held by `python3 scripts/check_caps.py --final`.
  - `mod <file>`: a test of `tests/mod`, written by the package of the last column with its own change.
  - `gate <command>`: a command of `bash scripts/verify.sh final`.
  - `bench <key>`: a line of `docs/evidence/scorecard-9.8.5.json`, written by `python3 bench/scorecard.py --gate`.
  - A value after `=` is the `final` the file must hold for that key; `python3 scripts/check_done.py --final`
    compares the two (row `D75`).
  - **Proves less:** what the check does not show of its promise. Four limits come back often and are named by
    these words. *The scripted person* takes the recommended option of every question and answers at once, so a
    count of dialogs holds for that person only. *Scripted agents* write what their script says; a real model may
    leave a rule open, miss a fix or read less. *One fixture*: the check runs on the small scripted project named,
    with fake tools. *The mod only*: with the mod off nothing checks that a person, and not the model, made a call.
- **No model call.** `yes`: the check runs with the real CLI, scripted agents and a scripted person, and costs
  nothing. `no`: it needs a model and money, which only the owner's first message allows (note 1). `person`: it
  needs a reader. A row that is not `yes` and has no command says "No automated check" and what the pull request text
  must state in its place.
- **Passes after.** The package after which the whole row must pass and leave the list. The first package id of
  the cell is that package; brackets name the earlier packages that turn single assertions green. "It holds at the
  head" means the check passes at `10e965a` already, is never on the list, and must never fail. "Kept by" names
  the later packages most likely to break the row.

The parts: A, a run in run units (`D01` to `D29`); B, the eleven rules of the brief, `docs/plans/one-go/README.md`
section 6 (`D30` to `D40`); C, the 16 defects and the 4 flips of pull request #115 (`D41` to `D57`, ids of
`docs/plans/one-go/evidence/v-pr115.md`);
D, the replay of the measured run (`D58`, `D59`); E, migration (`D60` to `D65`); F, the caps and what keeps the
product from growing back (`D66` to `D79`); G, the suites that existed before, CI and the pull request text (`D80`
to `D89`); H, the bench gate (`D90` to `D98`); I, promises of the plan that had no row before the audit of the kit
(`D99` to `D106`); J, the owner's decisions of 2026-11-16: the summary of what happened, the short README and a
run with a real model (`D107` to `D109`).
