### R0-R1-4 (low): U18 is still open: 3.10 reaches a command as 3.1, and a secret is masked by its name only

**The promise:** pr-115-fixes.md section 3: "U18 | Secrets are masked by name only; `3.10` reaches a command as
`3.1` | WP29 (the config reader keeps such a value as text) and WP20 (what is shown of a block)"

**What the second checker found at the audited commit:**

I could not refute it: both halves of U18 behave exactly as at the base of pull request 115, and nothing records a
decision to leave them.

**The promise is real.**
- `docs/plans/one-go/pr-115-fixes.md:89-92`: "The build takes 24, keeps one as shipped and names it to you, and
  drops four. ... the package named closes it, and WP32 reads the list at the end: a line still open goes into the
  text of the pull request. Where the spec of a named package does not carry the point in its own words, the point
  is still that package's."
- `pr-115-fixes.md:113`: "U18 | Secrets are masked by name only; `3.10` reaches a command as `3.1` | WP29 (the
  config reader keeps such a value as text) and WP20 (what is shown of a block)".
- `done.md:191` (D106): "The 29 smaller points of pull request #115 are each closed by the package that
  `pr-115-fixes.md` names, kept and named, or dropped."

**U18 is none of those three.** WP29 and WP20 are both marked done, `PROGRESS.md:310` is unticked, and neither
package's notes mention U18. No test covers it, and the number parse and `mask` are unchanged against `10e965a`.

**One part of the auditor's claim is premature.** WP32 is still "doing" (`PROGRESS.md:75`), and draft pull request
117 says its final text comes with WP32. So the missing mention in the pull request text is not yet a breach. WP32's
first step must either fix U18 or list it under "Not done".

**Why low, not medium.**
- The plan itself files it among the "smaller points".
- Both halves need a hand-written config line. `doctor.propose` copies only database port and host values from CI
  (`scripts/doctor.py:144-152`), so the product never writes such a value itself.
- Quoting the value works: `"3.10"` stays `3.10`.
- A secret in the run line is already plain text in the config file that every agent can read.

The silent wrong value is still a real trap for version numbers such as `3.10` or `1.20`.

All runs were on a detached worktree of `dc108ee`, removed afterwards, in a scratch git project whose
`.claude/temper.config` held the auditor's block.

**The value `3.10` becomes `3.1`.**
- `scripts/temper config get setup.env.PYTHON_VERSION` printed `3.1`.
- `run_env.load_setup()` returned `'env': {'PYTHON_VERSION': '3.1'}`.

  `"3.10"` printed `3.10`.

  dc108ee -- scripts/config_yaml.py` shows WP29 changed `get` and the defaults but not these lines.

**A secret under a non-credential name is shown.**

  doctor: it may start a service)` and `PYTHON_VERSION=3.1`.

  export DB_PASSWORD=<left out> API=sk-live-abcdef0123456789; variables: PYTHON_VERSION=3.1. ...`.

**Bookkeeping.**

  ...`.
- A search for `U18` across `scripts`, `tests`, `hooks`, `agents`, `reference`, `docs/*.md` and `CHANGELOG.md` finds
  nothing; it appears only in the plan kit.
- The WP29 spec keeps the number parse as it is (`wp/phase-7-and-8-front-and-surface.md:812-814`), and the WP20 spec

**Smallest fix:** In `scripts/config_yaml.py:46-50`, keep a scalar as a number only when the number prints back as
