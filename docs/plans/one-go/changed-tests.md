# Changed tests: every assertion of the base that was changed or removed, and why

This page is row `D84` of `docs/plans/one-go/done.md`. `python3 scripts/check_changed_tests.py` reads it: an assertion
of a test of the base (`10e965a`) that the tree no longer holds as it was must have its name in a code span in the first
column of the table below, and its file in a code span in the second: a row covers a change only in a file it names.
The same holds, from the commit that first added each file to the branch, for the case files 43 to 46,
`scripts/e2e/accept.ts`, `scripts/e2e/slow.ts`, `scripts/e2e/broken.ts` and the table of `done.md`, whose rows are
named by their id (`D84b`).

The name of an assertion is the one the checker prints: its first quoted string that holds a letter and that no other
assertion of its file at the base holds as a quoted string (for a call of `expect(` over several lines, its message is
read too). Failing that, it is the statement itself, its lines stripped and joined by a space, with `#k` after it when
the file holds that statement more than once. So a name identifies its statement, and a line here covers that one alone.

A package that changes or removes such an assertion adds its line here in the same commit. It never changes what a check
of `done.md` asserts: only a name may be corrected, and the line says so.
