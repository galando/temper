# v7.1 — Keep the Promise

**Proposed release:** v7.1.0
**Current version:** v7.0.1
**Theme:** Don't chase superpowers feature-for-feature. Temper has exactly one wedge no
competitor can copy in prompt-space: *the process is impossible to skip, and there's
evidence it ran.* This release does three things only — fix the two places where that
promise is currently false, remove the one adoption gap that loses users in the first
five minutes, and publish numbers instead of claims.
**Status:** Planning · **Date:** 2026-07-22
**Supersedes:** the 8-workstream "close every gap" draft. Five of its eight workstreams
are cut or deferred below, with reasons — deletion is the point of this document.

---

## Thesis

Superpowers' moat is a network effect (~259k stars, 10+ harnesses, 14 à-la-carte
skills). No roadmap closes a network effect, and every workstream spent imitating its
surface area is a workstream spent fighting on its turf with less distribution.

Temper's moat is the deterministic spine. The winning position is narrow and honest:

> Superpowers tells the model to follow the process. Temper makes the process
> impossible to skip — and can prove it, in CI, with numbers.

Everything in this release either (a) makes that sentence *true* where it currently
isn't, or (b) makes it *visible* to someone who has never heard of temper. Anything
that does neither is out.

## The three items

### 1. Integrity fixes — make the headline claims true (do first, smallest diffs)

Two places where temper's own pitch is currently false:

- **The design gate is a rubber stamp.** `scripts/temper:807` hard-codes
  `design) reqs_json='[]'; all_pass=1` — an always-PASS verdict, which directly
  violates "no verdict without evidence." Give it the same mechanical shape as the
  other gates: `design.md` exists, contains an alternatives section with ≥2 entries,
  contains a risks section, each risk maps to a plan task. All checkable with the
  existing gate machinery; no new concepts.
- **Raw `git commit` is ungated on a fresh install.** `commands/init.md` only
  *recommends* running `scripts/hooks/install.sh`. Until the user does, the flagship
  guarantee — commits physically blocked on FAIL — doesn't exist. `/temper:init`
  installs the native pre-commit hook itself (idempotent, with a printed opt-out),
  instead of asking.

Optional rider if trivial: hand-rolled YAML parser (`scripts/temper:154-214`) emits a
loud validation error on config it can't parse, instead of silently misreading. Not a
rewrite — just refuse-loudly.

**ROI:** a day or two of shell + fixture updates. Without this, item 3 publishes a
benchmark of a system whose own gates don't meet its bar.

### 2. Auto-engagement lite — stop losing users in the first five minutes

The one real adoption gap: superpowers engages on any task; temper waits to be
summoned with `/temper`. Close it with the two cheap layers only:

- A `using-temper` meta-skill whose description auto-triggers on feature/bug/refactor
  shaped requests, including the rationalization counters ("this is just a small
  change" → "small changes are exactly what blast radius is for").
- A `UserPromptSubmit` hook that pattern-matches feature/fix-shaped prompts and
  injects a one-line suggestion to enter the pipeline. Deterministic detection,
  consistent with the spine philosophy.

**Explicitly deferred:** the PreToolUse Edit/Write guard that blocks edits without an
active build-state. It's the most novel idea in the original draft, but it's also the
most likely to infuriate users if the detection has false positives. Ship the two
soft layers, watch, then decide — it's a config flag away later.

**ROI:** one skill file + one small hook script. This is 80% of superpowers'
engagement advantage at 10% of the surface area.

### 3. Publish numbers — temper vs. bare Claude Code (not vs. superpowers, yet)

Temper already owns the only self-eval harness in this space (`evals/`, seeded-defect
fixtures, CI). Extend it into a small published table: the same seeded-defect
fixtures run under (a) bare Claude Code and (b) temper — defect-catch rate,
false-positive rate, tokens spent. Report lands in `docs/evidence/` and the README.

**Deliberately two-way, not three-way.** Running a competitor's plugin "fairly" is a
methodology minefield (version drift, prompt tuning accusations, harness differences)
and turns a data release into a flame war. Bare-baseline numbers already prove the
core claim — *gates catch what exhortation misses* — because bare Claude Code *is*
the exhortation-only condition. Add superpowers as condition (c) later only if the
two-way table lands well and someone external asks for it.

Side benefit: the token column gives real data for whether the reference-file diet
(cut, below) is actually needed, instead of guessing.

## Cut or deferred, with reasons

| Original workstream | Verdict | Why |
|---|---|---|
| WS2 — unbundle into 14 à-la-carte skills | **Cut** | Fights on superpowers' turf; dilutes the integrated spine, which is the product. Revisit only if users ask for a specific standalone piece — then extract that one. |
| WS4 — worktrees + fresh subagent per task | **Cut** | Biggest rearchitecture in the draft, marginal outcome gain, and token-expensive — it contradicted the same draft's WS5 diet. |
| WS5 — reference/ token diet (6,412 lines) | **Deferred behind item 3** | Real cost, but a grind with no user-visible win. Let the benchmark's token column say whether it matters and where; if it does, split only the top two files (`review.md` 1,246, `plan.md` 1,086). |
| WS8 — multi-harness ports + marketplaces | **Deferred, one exception** | No proof, no pitch — porting before item 3 exists just distributes an unproven claim. Exception (cheap, correctness): regenerate the Cursor export in release CI, since the frozen v6.0.1 snapshot ships pre-spine behavior under temper's name. |
| WS1's PreToolUse edit-blocker | **Deferred** | See item 2 — soft layers first. |

## Sequencing

1. **Item 1** (integrity) — nothing else is honest until the gates meet their own bar.
2. **Item 2** (engagement) — the only first-impression gap that matters.
3. **Item 3** (numbers) — the durable differentiator; also decides the diet question.

Three items, one release. If v7 was "trust through determinism," v7.1 is shorter:
**keep the promise, then show the receipts.**
